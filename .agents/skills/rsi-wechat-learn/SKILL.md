# 微信能力验证与报备

适用于本人及工程任务会话、好友和群聊回复会话。任务留在当前负责会话。
从[原请求与会话协作协议](../../../harness/DESKTOP-WECHAT.md)核身份、目标和回执。
确需另一会话协作时，核对用户授权和已有执行者，只交办一个有明确结果的子项，
再把证据汇回原负责会话。

1. 找到第一处缺口。
   - **触发**看原生身份、入站持久化与 ACK，以及接收器中的原 ID、输入摘要、
     目标会话和附件。已入队但看不到输入时，维护按协议的只读对账入口核入队与
     实际轮次；轮次缺失保留为待复核。
   - **发送**从该轮冻结结果查到原 V2。沿协议的 `desktop_reply status` 查询
     同一 ID、会话和轮次。`pending` 表示等待回执，`unknown` 表示结果待确认，
     `not_sent` 表示未发送；`sent` 才能报告已发送并引用该回执返回的原文。
     `quiet` 保留为本轮静默决定。图片、文件和原生表情各按实际载体核验。
2. 在当前已授权范围试一条可验证的做法。例如在本人已授权生成且找不到贴切素材时，
   按语境做一张。普通聊天的权限以原包为准。需要改代码或操作客户端时，按原协议
   的工程或运维授权执行。保持原 ID 和结果，未知发送先查原回执。
3. **RSI Skills**把已做成的路径留给下次使用。确定性收发问题修对应代码，
   可复用的判断和操作步骤更新现有 skill，单次案例保留一条脱敏经验。写清适用
   场景、已核实的证据和下次命中的入口；下一条适用请求用于核实际复用。
   做成一条新路径后给维护会话一次短报备。跨会话发送以可核验的用户授权和
   实际目标为准。只发脱敏经验。没有报备渠道时，在当前 Codex 会话留下同样的
   摘要，供维护只读复查。

报备格式：`触发 / 发送 / RSI Skills｜遇到的情况｜有效做法｜实际证据与阶段｜下次在哪一步复用`。
把样本、隔离验证、已部署和真实送达分开写。一次授权发送只记录为单次案例。
要长期采用的做法须有用户明确指导或维护验证。图像、正文、完整原 ID 和私有素材
留在原记录，报备只带经核对的摘要与证据类型。
