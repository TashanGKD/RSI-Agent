# 2026-11-06：同仓源码与共同方法更新

本轮更新原Secretary Workbench私有交接包，沿原三工程和六边界，不建立生产镜像。源文件按稳定截止冻结，前后manifest及逐文件SHA在私有交付证据保留；仓内只发布不带私人绝对位置的逻辑来源和哈希。

选入：记事本4.4事项/实际工作元数据与前端、契约和测试；AUP当时有效的原生读取与operations模块；原ClawBot通信/多模态/同一持久对话适配；原宿主协作薄客户端及其直接依赖；共同digital-employee的30文件；原审计/录制等既有通用部分和许可。未同步整个Skill库、科研/公司项目或Mac采集器工程。

微信源码覆盖dispatch批量准入/状态/独立核账、回复与普通交付的有界调度、Policy v2、原生唯一身份与标题、准备/确认/单Send、未知停止与同原请求核账，以及已发送后自有导航/草稿收尾。读取侧保留卡片与合并记录的现有安全解析和覆盖缺口。普通文件资源兼容、图片解码预算和锁按冻结代码执行；不能只靠一个能力标签推出所有场景已验收。

为了离开原机器复用，本包调整了源码/运行目录、SSH别名、宿主路径和已有对话身份为配置或合成值；抽取必要原生编辑/文件辅助函数，没有附它们原业务服务的联系人、范围或资料。测试的旧固定日期、字体和资料文件改用隔离合成样例。上述变动只在打包副本，生产树没有改。

旧单差异核账中的真实job、message、作者与接受文档注册已整体移除。通用校验代码保留，但 `original_deviation.CASE=None`，默认不接纳任何历史特例；普通精确/单个末LF核账继续原规则。包里没有真实接受文档、回执、实例JSON或允许其他新消息被归一化的注册。需要在另一安装处理具体原单时，必须依据该安装自己的真实业务/原生证据，不能复制这里的测试当接受依据。

数字员工Skill保留职责、协作、工作本、按需学习、交付及接续方法；源码树中的ROLE/STATE/JOURNAL等仅为空白 `.template`。作者自己的岗位资料、CURRENT、经验、业务本、事件注册、调度与监控运行状态均未选入。脱敏后的历史安装说明仅说明方法与依赖，不代表新机已具同一系统负责人、账号或事件入口。
