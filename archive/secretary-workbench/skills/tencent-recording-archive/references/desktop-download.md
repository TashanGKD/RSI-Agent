# 腾讯会议客户端下载原录制

## 已验证路径与限制

2026-10-16 的两场答辩归档记录确认：MCP 查询与转写接口可用，但 `get_record_addresses` 实际只返回 `view_address`；`yt-dlp` 对该观看页返回 Unsupported URL，浏览器进入登录页。后来读取本机腾讯会议客户端，发现已有登录态，直接通过客户端官方下载成功。不要把这次网页失败推广成“所有腾讯会议视频必须网页登录”，也不要把历史接口响应推广成永远没有直链。

可复用的是“在当前 UI 中查找云录制→核对目标→打开下载列表→选择视频→等待完成”，不是某一版本窗口的坐标。

## 操作方式

1. 使用当前环境提供的电脑操作工具选择腾讯会议应用，并阅读工具返回的操作文档。需要 inventory 才获取应用列表。客户端没运行可通过该工具正常启动。
2. 读取界面，确认是当前账号。遇到登录页请用户自行登录；不要索取账号密码或从其他应用复制登录态。
3. 找到云录制/录制入口，通过主题、日期定位。进入详情核对标题、日期、时长等，不能只匹配“视频-1.mp4”。重名未消歧就不点击下载。
4. 在当前界面寻找“更多”“下载”“下载文件”等实际入口。历史成功路径是：录制详情的更多菜单→下载列表→视频旁下载按钮。弹窗需新快照确认，按钮位置可能变化。
5. 选择原视频文件；多个视频轨道、布局或分段时识别各自含义。用户只需某个布局时按其要求；未明确而影响完整性时展示候选。只下载视频不等于取得独立的屏幕共享/PPT源文件。
6. 用保存对话框、下载列表或完成提示确认目录。通常可能在 Downloads，但不得假定。可在已确认的下载目录中，按此次目标文件名、下载时间缩小范围检查；不要遍历无关个人资料。
7. 等到客户端完成提示；检查不存在 `.part/.download/.crdownload` 等临时后缀，并在两个相隔约2秒的观察中大小不变。稳定大小本身不证明完整，随后仍需 ffprobe；时长与录制详情有明显差异时暂停核对。
8. 归档时复制，不移动/删除用户 Downloads 原件。完成归档后回读 manifest 和 SHA-256。

窗口切换、用户正在操作或弹出登录页时重新读 UI，不盲点。无需为了本任务修改云录制的分享、下载权限或所有者。无权限时使用现有腾讯会议 skill 的明确申请流程；需用户批准的动作不能跳过。

## 转写与视频对照

转写时间戳通常是相对录制起点的毫秒数。先读当前返回字段确认单位；不要从机器转写最后一句的时间直接认定视频总长度，因为开场等待、静默和结束画面也占时长。多段录制各有独立时间轴，不能直接拼同名 PID。

本地脚本的 transcript 命令仅接受当前已核验的 `minutes.paragraphs / sentences.words[].text` 结构，并对照完整 PID 清单。上游返回包装层可解包，但不能丢弃未识别段落，或用摘要替代缺失句子。
