# 官方网页下载与分组核对

使用电脑操作工具读取当前界面。默认使用 Chrome，按用户当次指定的浏览器调整；用户自用的 Edge 不操作。不要复制其他浏览器登录态，也不要读取会话数据库或令牌。登录和协议交给用户自行完成。

## 先区分页面身份与文件身份

一个父活动观看链接可能对应主会场、多个分组和多个分段。API 给不同文件返回同一观看链接时，链接本身不证明文件正确。

核对活动标题、日期、目标分组名与文件编号。播放器出现控制栏后，可用底部当前录制名称旁的切换入口展开房间列表。等列表实际加载完成再选目标；不要因第一帧只有主会场就判断没有分组。暂停播放、必要时静音，可以减少实时字幕刷新对定位的干扰。

外部汇总表中的期次只是待核对标签。链接打开并重新加载后，若页面标题、日期或文件身份仍属于另一场，记录错链及实际身份，不把它计为目标期次已补齐。页面初始加载时可能短暂显示禁用按钮；等录制身份和业务内容就绪后再复核，不能把占位状态直接解释为下载权限拒绝。

每次动作使用最新 UI。菜单会自动收起，元素编号会随页面刷新而变；读取后立即操作，过期就重新定位，不复用历史坐标或旧编号。一次 UI 动作报错不代表它没有生效，先读取结果再决定下一步。

选房后核对当前文件编号，例如页面实际呈现的录制标识。再用房间名、开场人物、话题和时间交叉检查；数字编号相同只说明产物关联，不能单独证明选对了房间。

## 两种已实测的官方入口

| 页面提供的入口 | 原视频 | 完整逐字稿 |
|---|---|---|
| 所有者录制详情 | 更多 → 录制文件 / Recordings → 对应视频下载；按需要选择单流合成布局 | 优先 API 完整 PID 链路；也可用官方导出 |
| 分享录制页面 | 页面自身 Save as → Export to local → Video Content | Save as → Export to local → Transcription Text → Markdown → Export |

“Export to local”可能需要再次点击才展开下一级。它是腾讯会议页面菜单，不是浏览器的“网页另存为”。导出动作只表示已请求，不表示下载完成。

如果先打开 Markdown 对话框，后续操作前只关闭这一对话框，勿误关浏览器窗口。若点击后结果不明，先查下载记录，不能重复点击整批导出。

导出响应可能异步返回。**保持原录制页面，直到对应条目实际出现在浏览器下载记录；不要点击 Export 后立刻在同一标签导航下一场。** 可以切到下载记录标签检查，让原页面继续完成请求。先前点击过但没有文件时，先核对下载历史与本地文件，区分失败、尚在生成和根本未启动，再决定是否重试；按钮点击成功不等于文件已取得。

## 批量父活动导出的重要限制

分享页导出可能下载父活动的全部房间、说话人布局和共享屏幕布局；当下选中某个房间，不保证导出仅包含该房间。取得文件后按身份匹配，只将目标房间归为本任务交付。

视频 `Quality-N` 和逐字稿 `Text-N` 的序号不一定对应。可在 Chrome 下载记录中搜索已核准的 `record_file_id`，核对视频与 Markdown 官方下载条目中的文件编号，再记录本地文件名。读取签名链接时只保留数字文件编号，不输出或保存签名查询串、Cookie 或令牌。并以文稿开场、视频人物、时间轴再次核对。

旧文件名存在时，Chrome 可能加 `(1)` 后缀；不要按第一次文件名猜当前下载。未完成文件、零字节文稿和不同房间产物都不能冒充完整目标文件。

## 传输和验收

点击后的工具等待时间与视频传输时间是两件事。工具超时后，下载可能仍在后台进行。先检查已有条目和进度；目标仍在传输时，不重发整个父活动的导出。

父活动包含很多房间时，估算下载、归档副本和后续处理所需空间。暂停本轮确认无关的房间文件，保留目标的传输；勿暂停用户其他任务或删除 Downloads 原件。已暂停、网络失败、传输中、已完成分开记录。对目标恢复下载后独立检查完成状态，避免无限重复恢复或生成重复副本。

只有下载记录显示完成、临时后缀消失、文件大小稳定，才进入本地 `ffprobe` 与归档哈希核验。还要核对视频与录制时长；录制存在长时间空场时，最后一句转写时间不等于原视频总长。

API 全文按 PID 验证完整性；网页官方 Markdown 则保留原件，记录对应录制编号与导出来源，不伪造 API 完整性证据。开头或结尾从内容中途开始时，明确标注源录制缺口，不能补写不存在的原话。

网页导出须确认选择的是整份 Transcription Text，未设置选段、筛选或摘要范围；若界面提供段落总量或全文计数，和导出文本比对。核对说话人和时间顺序，至少将开头、中间若干时间点及结束语与网页转写或视频交叉核对。非空文稿、正常首尾本身不能排除中间遗漏。拿不到独立全文索引时，写明“官方全篇导出，未完成独立逐段覆盖验证”，不要把这一证据等级等同于 API PID 全集核验。发现缺失或只有选段时保留实际覆盖范围，不称全文完整。

在本地每份归档旁保存 `source-evidence.json`，不覆盖归档脚本生成的 manifest。至少记录：父活动与目标文件编号、房间名或其核准依据、会议日期、真实视频/文稿文件名、各自完成状态、导出方式与范围、文本段落数和首末时间、已交叉检查的时间点、完整性等级及尚存缺口。无法取得的值写未知；不得填成已验证。只保存身份与核验元数据，不保存签名URL。既有文件重复处理时先比对，不覆盖冲突证据。

## 确实受阻时

“更多”只有举报不能单独证明禁止下载；但目标文件已核准、官方本地导出明确禁用时，不能用抓取媒体流绕过限制。按上游 skill 获取权限申请预览；只有用户明确确认后才提交申请。如果官方返回“该录制不接受审批申请”，如实列出对应活动和链接，需要录制所有者开放下载或提供原件；继续处理其他允许的来源。

UI 等待或 API 错误不能推广为所有腾讯会议录制都不可下载，也不能据少量成功宣布整批完成。
