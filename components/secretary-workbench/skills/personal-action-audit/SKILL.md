# 全源待办梳理

把原始信息变成「我有哪些事需要处理」，包括承诺、应回消息、身份适用的通知、自己的计划和等待事项。高召回保留候选，但不把候选数量当作未完成数量。

## 日期和范围

- 「8月以来提出了什么」是**来源期间**；「截至某日还有什么」是**截至时点**；「某天要做什么」是**到期日**。到期日查询也要检索此前产生的未决承诺，不能只读当天消息。
- 沿用用户明确的最早阅读日期、来源范围和排除项。不因执行时间较晚就把更早提出的旧事项冒充本期新增。
- 解释用户日期使用客户端时区，保存消息原时区。区间用本地零点至结束日次日零点，再转换查询；不能截断UTC日期冒充本地日期。
- 区分来源窗口、状态截至时点、到期日、数据快照。只有日期就保留日期，不补造23:59。文件名、下载日、上传日不能自动当会议发生日。
- 单个模糊日期若会明显改变结果，简短确认；否则说明采用的解释并开始工作。

## 先保证没有漏渠道

盘点本地档案、已连接服务及浏览器现有登录，不先安装新系统。读取当前工具帮助或真实结构，不猜接口/数据库字段。详细入口和认证处理见 [来源读取](references/source-reading.md)。

1. 建立会话、邮箱、会议及附件目录，保存完整原生目录/逐页响应的独立回执及哈希，再选阅读顺序。记录查询日期、快照、分页终点、来源数量、失败和权限缺口。不能从已选队列反推「完整目录」；枚举与语义阅读分别记。
2. 范围内**所有群和私聊均纳入阅读队列**；没有本人发言、未被点名、不是常聊群不能成为排除理由。身份适用的「@所有人」、实验室、单位、课程、财务通知可能直接产生个人义务。
3. 关键词只用于定位、排序和交叉核对。报告「全部」时，不能用命中片段替代范围内正文连续阅读，也不能用未命中证明没有事项。
4. 按稳定来源ID和快照记录已读范围，分批读、断点续读。机械导出、列目录、搜索结果、预览头尾不算全文读完。
5. 先读可用文字、语音转写和会议逐字稿，再按用户媒体策略处理图片、文档内件、转发消息、视频和失败语音。未读内容留缺口；OCR、转写、抽帧、原图和原音分别记录。

不要再次复制整份聊天库、媒体库或应用运行目录。复用内容哈希相同的原文和已读检查点；新增提取按有限批次执行，只保留必要的小型文字和定位，不启动未验证的常驻采集器。

## 通知要追到可判断的行动

继续读取链接、完整通知、附件、名单、邮件和更正版。能从机构官网取得原件就先取得，不因邮箱暂不可用停止全部工作。查到上级通知后，仍需核对实验室/单位的后续个人安排。

逐条判断：

1. 面向谁：全员、某身份、指定名单、特定年级/项目，还是自愿报名。
2. 本人为何适用：名单具名、真实身份、直接请求或明确承诺。@所有人意味着要审查，**本身不证明必须参加**。
3. 要做什么：反馈、回复、填表、签字、交件、缴费、准备汇报、参加、确认或选择，明确责任人和交付对象。
4. 哪个期限属于本人：区分个人反馈/交件、秘书汇总、对方审核/付款、活动举行；不能把秘书报送日写成本人DDL。
5. 后续是否改变：新版本、延期、取消、已发送、已收件、已审批、已付款、已完成逐阶段核对。无回执只表示状态未知。

分为：**明确事项**（承诺、直接请求、已确认身份要求）、**待判断**（可能适用、条件/归属/现状不清）、**知会／可选机会**（相关但无必须执行要求）。明确适用与执行进度是两件事；适用已确认也可能不知道是否已做。

用户自己的探索、愿望和计划保留为意愿／条件触发，不改写成对外承诺。等待对方也记录；不要为每个未知再创造一个让用户自查的新任务。

## 每项都能回到原文

主视图：**对谁／为自己｜我要做什么｜提出时间｜紧急程度（交付时间）｜当前状态｜依据**。通知可附适用条件、材料、地点、等待对象和变更。

- 保存发送人/发言标签、原时间、稳定原生ID、附件版本/哈希、页码/行号/单元格及必要原话。
- 用「渠道+账号+原生ID+内件定位」形成全局唯一ID；不同批次重用的局部编号不是同一条证据。
- 「好的」等重复短句必须定位到原消息和正确上下文，不能链接到同文件第一个匹配句。
- 设备名为本人、共享麦克风或AI纪要不直接证明本人承诺。转写的人名、金额、日期有疑点时保留原文并核听。
- 邮件可见正文抄录、提取文字、OCR和ASR标明性质；不冒充原始MIME、人工核听或看过签章。
- 按**对方+交付物+事件**合并，保留成员证据及状态变化。同名合同、不同网站、不同付款批次分别判断。
- 已发不等于验收，审批不等于到账。完成/取消只关闭原文支持的具体动作，不关闭同主题后来的新请求。

## 反向补漏与完成门槛

再从原文检查通知/@全体/身份要求、报题/回复/签章/付款、自己的意愿、等待对方和日期变更。将每个要求映射为事项、已有项补证、具体已闭合、知会/可选或待判断；不能只复读已生成主表。

对「全部」、跨源盘点或长批次补漏，按 [审计包约定](references/audit-packet.md) 记录范围、覆盖、证据、追查队列和事项，并运行：

```bash
python3 scripts/verify_audit.py /absolute/path/to/audit.json
```

默认只读、不联网、不读取密码、不修改源文件。原文在包目录外时，仅可用 `--source-root /specific/source/directory` 显式允许读取。不要为通过检查把未读改成已读。

目录分页/时间覆盖已核对、范围内正文连续读完、必要追查已闭合、相关未读/归属不明材料已处理，才能报告**本次声明范围内覆盖完成**。否则交付已找到的事项和缺口，明确部分完成。校验通过证明账本/引用一致，不是语义识别绝无遗漏的数学保证。

私有工作目录保留主表、完成/取消历史、宽口径候选、覆盖缺口和原文依据。不要把私人聊天、令牌或密码复制进本Skill。单通知可直接交付原文和行动，不强制搭建新系统。

本技能不授权发送回复、报名、付款、提交、修改正式任务或创建定时任务。已授权读取不重复询问；必须本人完成的登录验证/密码设置再交接。登录受限时不暴力重试。
