# 来源读取与追查

优先复用有出处的既有提取和检查点，再用可用的官方连接器/CLI或用户指定浏览器的现有会话。旧快照不是实时全量；记录最新已存时间、账号和未导入部分。

- 微信：会话目录与范围内完整消息，保留群、实际发送人、原生消息ID和转发层级。现成转写标ASR；失败语音列队列，不静默丢掉。
- 邮件：从当前UI/连接器确认账号，查完整通知标题、发件人、最新往来和附件。正常读信可能改变已读标记，但不额外删除、归档、回复、转发或标记。不为统一浏览器而退出可用会话。
- 会议：完整逐字稿及参与/说话人信息。多轨、不同格式、相同正文不等于不同会议。上传时间与实际会日分开，来源确认后再归日期。
- 文件：同名按消息、日期、内容哈希和对象区别版本。转发空壳、压缩包目录、部分提取或原件缺失均不算完整读取。压缩包先检查路径/大小，只提取所需内件，不执行内件。
- 官网：核对年份、单位、版本、附件及后续安排。官网与邮件名单确认同一批，不因同名就合并。

## 通知追查示例（合成数据）

群中「11月考核，@所有人」→原件区分年度/中期与年级→名单确认本人类别→实验室后续邮件给报题、交表、举行日期/地点→再核后续修改与本人交付依据。

个人反馈、交表、准备/参加分别识别。秘书排期和汇总日不当个人截止；同一包有中期表不意味着本人要填全部表。该群即使本人一条消息没发，仍在阅读范围内。

## 登录与身份

用当前UI/连接器核实登录身份，不只靠站点标题或某邮件收件人。账号显示地址与用户提供地址不同，记录差异；无证据不宣称是等价别名或已找到失败根因。

不读取密码管理器数据库、复制Cookie/会话令牌或绕过认证。正常登录及用户自行输入/保存密码沿用已有授权；新密码、短信和系统验证遵循所用工具的交接要求。控制失败先确认状态并有限重试，不反复开页、重试相同密码或自动改代理/系统安全设置。
