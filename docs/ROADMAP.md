# RSI Agent 路线图

更新于 2026-11-21（北京时间）。本文件只保留尚未完成、正在推进或等待验收的目标，不保留完成历史，也不作为固定交付日期或服务等级承诺。

项目推进方向：先让微信接入、任务执行和结果回传可靠运行，再把真实案例中的经验转化为可复用、可评测的能力。经验报备与复用贯穿各阶段，工程实现仍保持一个当前改进项。

## 使用规则

- 每个目标保留稳定编号、优先级、依赖、下一步与验收标准。状态使用“待规划 / 待实现 / 进行中 / 待验收”。
- 代码完成或 CI 通过后，仍有部署、恢复或真实场景验收未完成的目标继续保留，明确剩余范围。
- 达到验收标准后，从本文件移除目标；已经交付的变化进入 [CHANGELOG](../CHANGELOG.md)，实际运行与验收证据更新到 [CURRENT](../memory/CURRENT.md)。
- 合并、部署和验收分别核对。主线已合并的能力不自动算作所有部署环境均已验收。
- [todo](../memory/todo.md) 承接近期执行任务，[decisions](../memory/decisions.md) 保存取舍；本文件不复制逐次故障日志、账号资料或私有回执。

## 推进顺序

| 编号 | 目标 | 优先级 | 状态 | 依赖 |
| --- | --- | --- | --- | --- |
| M1 | 稳定常驻与原请求恢复 | 当前 | 待验收，含交付收束 | 完成当前候选审查及维护窗口安排 |
| M2 | 常用消息与反馈的环境验收 | 下一步 | 待验收及补缺 | M1 的稳定版本与环境记录 |
| M3 | 可恢复安装、升级与维护 | 后续 | 进行中，仍有首装闭环缺口 | M1；M2 的支持范围 |
| M4 | 任务交付与受控记忆 | 后续 | 待规划及补验收 | M1、M2；明确的任务场景与权限 |
| M5 | 固定基线上的 RSI 优化 | 后续 | 待实现正式评测 | 稳定运行基线、任务集与独立评测 |

当前先收束 M1；M2 优先补现有支持范围的验收，避免同时扩大消息类型与平台范围。

## M1：稳定常驻与原请求恢复

**剩余范围**

- 完成 [PR #124](https://github.com/TashanGKD/RSI-Agent/pull/124) 的审查和交付收束，核对实际使用的源码、配置、Python、服务与原队列。
- 在有手机可用的维护窗口内，启用本机持久服务和 Windows 登录任务，验证发行版启动、系统重启、用户重新登录与回滚。
- 分别验收插电熄屏、锁屏、宿主睡眠及恢复。记录电脑需要保持唤醒的运行条件；若需要全天在线，再选择常开执行环境。
- 用受控故障覆盖断网、接收器退出、原单准备失败、已发送但清理未完成、回执晚到和结果不确定等状态。

**验收标准**

- 恢复沿用原账号、目标会话、令牌、输入和完成结果；已完成任务不重新生成，未知发送结果不重放。
- 已证明未发送且现场恢复的失败可收束，后续新消息继续处理；已接受发送只恢复原现场。
- 发送结果、清理状态和接收器/原生运行观察分别可查；晚到通知绑定原请求和原会话。
- 建议完成连续 7 天的真实使用观察，记录在线中断、人工干预及各阶段耗时。先建立基线，再制定成功率和 P95 延迟目标。

## M2：常用消息与反馈的环境验收

**剩余范围**

- 按部署环境建立“本人 / 好友 / 群聊”与“文字 / 图片 / PDF / Word / 链接”的支持和验收矩阵，只补缺失格子。
- 验收本机好友和普通群消息、普通群图、图片与文字/链接混合输入，以及新原生 Word 文件的完整回传。主线文件能力的具体限制以当前协议为准。
- 验收受保护草稿、联系人名称变化、布局不支持、客户端掉线及版本不支持时的反馈，避免根据错误码猜测存在某种附件或草稿。
- 补充公开链接读取的候选规则复用；需要时推进 [原生动态表情回复 #26](https://github.com/TashanGKD/RSI-Agent/issues/26)，单独验证素材来源和实际发送载体。

**验收标准**

- 每个场景关联原生身份、原消息、实际 Codex 轮次和原 V2 结果；附件同时核来源与字节摘要。
- 区分“代码支持 / 隔离验证 / 当前环境真实验收”；其他主机的成功记录不代替本机验收。
- 同名或不明确的目标不能误发；不支持、未取得正文或未取得附件时，准确说明读取范围。
- 静默、部分发送、未发送、结果待确认与已发送分别报告；候选经验经后续独立请求复用后再晋升。

## M3：可恢复安装、升级与维护

**剩余范围**

- 将首装中仍依赖人工适配的账号绑定、目标会话、发送器与服务配置收束到可检查、可续跑的流程。
- 明确保留扫码、账号归属和权限确认等人工步骤；其余步骤给出当前阶段、失败原因与下一步，不要求用户手抄账号 ID、令牌或调试脚本。
- 提供一致的状态入口，覆盖客户端、触发器、通道、接收器、待处理原单和需要维护的异常。
- 完成升级、保留兼容读取器、回滚与卸载的操作说明，并记录磁盘、内存、首装耗时和人工步骤。

**验收标准**

- 在另一台干净的受支持 Windows 环境验证安装、配对、用户新消息回传、中断续跑和重启恢复。
- 重复运行不会生成第二个回复器、替换原令牌、清空队列或覆盖未完成工作。
- 支持的系统、客户端版本、语言、缩放和布局有明确边界；不匹配时先报告缺口。
- 升级和回滚均保留原请求及回执，卸载范围清楚，私有账号数据不进入源码或公开诊断包。

## M4：任务交付与受控记忆

**剩余范围**

- 从现有工程任务框架中选择少量固定场景，贯通接单、执行、验证、产物或 PR、原会话反馈。
- 让任务执行状态与普通回复状态可区分，验证长任务不会占用普通消息的回复路径。
- 在现有显式笔记上，补齐检索、纠错、删除和跨会话隔离的真实验收，再逐步增加语义摘要与检索。

**验收标准**

- 工具执行由原生本人身份与请求类型准入，群昵称、网页和附件内容不能改变权限。
- 工程任务使用隔离工作区，保留原输入、工具结果、验证和可审查产物；恢复时不重复执行已完成的操作。
- 私聊、好友与各群上下文隔离；记忆修订和删除可核对，不向其他会话透露原始私聊资料。

## M5：固定基线上的 RSI 优化

**剩余范围**

- 按 [PenguinHarness 专项方案](../harness/PENGUIN.md) 建立公开任务集、独立评分规则、留出集和完整基线。
- 固定模型、工具、运行环境与比较条件，先评测一个指令或 Skill 候选，保留失败和退化案例。
- 在候选被证明有效后再接入受控发布；优化器自身的改进另设外层评测。

**验收标准**

- 对同一任务集和基线给出可复现的成功率、耗时、干预成本与退化情况。
- 候选不能接触留出集或修改自己的评分标准；不完整评测不宣布增益。
- 回归通过、提交 PR、工程修复与 RSI 增益分别记录；不以提交数量代替能力提升。
