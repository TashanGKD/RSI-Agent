# RSI Agent 路线图

更新于 2026-11-23（北京时间）。本文件只保留尚未完成、正在推进或等待验收的目标，不保留完成历史，也不作为固定交付日期或服务等级承诺。

项目推进方向：先让微信接入、任务执行和结果回传可靠运行，再把真实案例中的经验转化为可复用、可评测的能力。经验报备与复用贯穿各阶段，工程实现仍保持一个当前改进项。

## 使用规则

- 每个目标保留稳定编号、优先级、依赖、下一步与验收标准。状态使用“待规划 / 待实现 / 进行中 / 待验收”。
- 代码完成或 CI 通过后，仍有部署、恢复或真实场景验收未完成的目标继续保留，明确剩余范围。
- 达到验收标准后，从本文件移除目标；已经交付的变化进入 [CHANGELOG](../CHANGELOG.md)，实际运行与验收证据更新到 [CURRENT](../memory/CURRENT.md)。
- 合并、部署和验收分别核对。主线已合并的能力不自动算作所有部署环境均已验收。
- [todo](../memory/todo.md) 承接近期执行任务，[decisions](../memory/decisions.md) 保存取舍；本文件不复制逐次故障日志、账号资料或私有回执。

| 编号 | 目标 | 优先级 | 状态 | 依赖 |

| M2 | 常用消息与反馈的环境验收 | 下一步 | 待验收及补缺 | M1 的稳定版本与环境记录 |
| M3 | 可恢复安装、升级与维护 | 后续 | 进行中，仍有首装闭环缺口 | M1；M2 的支持范围 |
| M4 | 任务交付、定时任务与受控记忆 | 后续 | 待规划及补验收 | M1、M2；明确的任务场景与权限 |

当前先收束 M1；M2 优先补现有支持范围的验收，避免同时扩大消息类型与平台范围。

## M1：稳定常驻与原请求恢复

本机已完成：systemd 持久服务与 Windows 登录任务启用（`45e04c7`），WSL 受控重启后服务、布局与真实收发均恢复验收通过（2026-11-22，证据在私有运行目录）。剩余范围：

- 验收系统整机重启后的自动恢复与回滚；核对当前部署版本与最新主线的差异并按维护窗口升级。
- 分别验收插电熄屏、锁屏、宿主睡眠及恢复。记录电脑需要保持唤醒的运行条件；若需要全天在线，再选择常开执行环境。
- 用受控故障覆盖断网、接收器退出、原单准备失败、已发送但清理未完成、回执晚到和结果不确定等状态。

**验收标准**

- 恢复沿用原账号、目标会话、令牌、输入和完成结果；已完成任务不重新生成，未知发送结果不重放。
- 已证明未发送且现场恢复的失败可收束，后续新消息继续处理；已接受发送只恢复原现场。
- 发送结果、清理状态和接收器/原生运行观察分别可查；晚到通知绑定原请求和原会话。
- 建议完成连续 7 天的真实使用观察，记录在线中断、人工干预及各阶段耗时。先建立基线，再制定成功率和 P95 延迟目标。

## M2：常用消息与反馈的环境验收

**剩余范围**

- 按部署环境建立“本人 / 好友 / 群聊”与“文字 / 图片 / PDF / Word / 链接”的支持和验收矩阵，只补缺失格子。
- 验收本机好友和普通群消息、普通群图、图片与文字/链接混合输入，以及新原生 Word 文件的完整回传。主线文件能力的具体限制以当前协议为准。
- 验收受保护草稿、联系人名称变化、布局不支持、客户端掉线及版本不支持时的反馈，避免根据错误码猜测存在某种附件或草稿。
- 补充公开链接读取的候选规则复用；需要时推进 [原生动态表情回复 #26](https://github.com/TashanGKD/RSI-Agent/issues/26)，单独验证素材来源和实际发送载体。

**验收标准**

- 每个场景关联原生身份、原消息、实际 Codex 轮次和原 V2 结果；附件同时核来源与字节摘要。
- 区分“代码支持 / 隔离验证 / 当前环境真实验收”；其他主机的成功记录不代替本机验收。
- 同名或不明确的目标不能误发；不支持、未取得正文或未取得附件时，准确说明读取范围。
- 静默、部分发送、未发送、结果待确认与已发送分别报告；候选经验经后续独立请求复用后再晋升。

## M3：可恢复安装、升级与维护

**剩余范围**

- 将首装中仍依赖人工适配的账号绑定、目标会话、发送器与服务配置收束到可检查、可续跑的流程。
- 明确保留扫码、账号归属和权限确认等人工步骤；其余步骤给出当前阶段、失败原因与下一步，不要求用户手抄账号 ID、令牌或调试脚本。
- 提供一致的状态入口，覆盖客户端、触发器、通道、接收器、待处理原单和需要维护的异常。
- 完成升级、保留兼容读取器、回滚与卸载的操作说明，并记录磁盘、内存、首装耗时和人工步骤。

**验收标准**

- 在另一台干净的受支持 Windows 环境验证安装、配对、用户新消息回传、中断续跑和重启恢复。
- 重复运行不会生成第二个回复器、替换原令牌、清空队列或覆盖未完成工作。
- 支持的系统、客户端版本、语言、缩放和布局有明确边界；不匹配时先报告缺口。
- 升级和回滚均保留原请求及回执，卸载范围清楚，私有账号数据不进入源码或公开诊断包。

## M4：任务交付、定时任务与受控记忆

**剩余范围**

- 从现有工程任务框架中选择少量固定场景，贯通接单、执行、验证、产物或 PR、原会话反馈。
- 让任务执行状态与普通回复状态可区分，验证长任务不会占用普通消息的回复路径。
- 在现有显式笔记上，补齐检索、纠错、删除和跨会话隔离的真实验收，再逐步增加语义摘要与检索。
- 建立通用定时任务框架，把“一个任务一个脚本”（现有晚间摘要）收敛为统一注册与调度：
  - 私有任务注册表：本人原生身份、目标对端、周期表达式、内容来源（模板或冻结生成包）、启用开关与 misfire 策略（跳过 / 补最新 / 全补）。
  - 常驻调度循环扫描到期任务，按 `hash(任务 + 周期)` 生成幂等实例投入现有 V2 队列；不新建发送通道。
  - 每周期一条账本记录（pending → running → done/failed），失败判定查原回执，不以本地超时判失败。
  - 宿主唤醒后先对账错过周期再按策略处理；定时批量不得饿死实时聊天。
  - 任务增删改仅经本人私聊原生身份准入；现有晚间摘要迁移为首个注册任务并保持原 ID 兼容。

**验收标准**

- 工具执行由原生本人身份与请求类型准入，群昵称、网页和附件内容不能改变权限。
- 工程任务使用隔离工作区，保留原输入、工具结果、验证和可审查产物；恢复时不重复执行已完成的操作。
- 私聊、好友与各群上下文隔离；记忆修订和删除可核对，不向其他会话透露原始私聊资料。
- 同一周期重复触发或中途崩溃重启不产生第二次发送；错过的周期按声明策略处理并有账本可查。
- 用真实周期任务（如迁移后的晚间摘要）验证创建、修改、暂停、恢复与一次故障补偿。

## M6：Codex 会话交互与调度体验

设计参照：DeepSeek 2026-11 发布的 Super-agent 架构文与 MIT 研究原型 [dsh-superagent-prototype](https://github.com/deepseek-ai/dsh-superagent-prototype)（Router/Worker 双层、订阅直通、Inline & Spill 上下文、Outbox 先存后发）。本项目已有其多个等价物（原生身份准入、冻结包幂等、V2 先记账后发送），下列条目只吸收差异部分，不引入第二个运行时；原型自述为研究代码，只借鉴设计不直接引入依赖。

**剩余范围**

批次 1–2 已合并并部署（`6475450`，2026-11-23 维护窗口）。实机验收：内联协议生效（同型请求轮次 96.3s → 88.0s，不再读协议/技能文件），成功送达静默入账（无新增通知行），ID/摘要核验不变。**自动唤醒未达成**：Store 版 CLI 无完整本地包，`app-server daemon`/`remote-control` 均拒绝启动，`queue --resume` 仅告警；本次经用户授权的会话内唤醒消息才加载会话（入队到完成 414.8s，其中约 6 分钟为等待）。剩余：

- 打通自动唤醒：评估独立安装版 CLI 常驻 daemon（`app-server daemon bootstrap`）或经评审的桌面侧激活路径；唤醒失败必须落明确状态，不重投。
- 唤醒打通后重测入队到完成的端到端耗时（目标对齐基线 107.2s 以内并叠加轮次缩短收益）。

以下为后续批次：

- 聊天并发评估：按对端分片会话或临时会话处理普通聊天，固定可见会话保留给需要审计的任务；保持上下文按原生身份隔离。
- 双层化演进（Router/Worker）：把现有固定会话明确为只做准入、分派与对外回复的 Router，普通聊天与工程任务由隔离 Worker 会话执行、只向 Router 汇报；对齐现有 DeepSeek 群聊静默门与工程分流，不新增用户可见会话。
- 订阅直通：为“原请求 ↔ 会话/任务”建立订阅关系，同一对端或同一 PR 的后续事件由程序直通已绑定会话，不再每轮经 Router 重新判断；跨范围事件交回重新分派。
- 上下文 Inline & Spill：队列消息默认内联当前输入、相邻消息与关联对象 ID，长内容截断留续读入口；以原 ID 引用图支持跨会话链式召回，替代每轮全量读文件。
- 任务级 Watchdog：在现有进程健康检查之外，增加对“任务是否有实质进展”的周期巡检（模型判断停滞/偏航），异常先收束原单再通知维护会话；与 M1 故障演练共用回执证据。

**实施顺序与风险约束**

按依赖分四批推进，每批保留原生身份门与原 V2 校验兜底，新机制失效时退回“慢但对”的现状：

1. **Inline 精简（纯减法）**：内联协议要点、当前输入与相邻消息，长内容截断留续读入口；不新增读取工具与权限面。
2. **自动唤醒与回执瘦身（局部改动）**：唤醒失败落明确状态、不重复激活、不重投消息；成功送达静默入账后，保证账本查询入口可用，失败/部分/清理未完成仍通知原会话。
3. **双层化与订阅直通（需授权设计）**：直通的是资料不是权限——每跳沿用当前认证包的原生准入，发送前 V2 身份校验不变；借鉴 Mandate 语义，授权凭据记录策略版本，订阅不得继承旧授权；多 Worker 并发抢桌面锁的排队延迟需实测。
4. **Spill 与链式召回（最后上）**：recall 工具带调用方 scope，每跳做与首次注入相同的准入检查，跨 scope 引用只示存在不给内容；硬预算（每轮跳数、单跳与总召回字节上限），超限明示并停止；摘要从结构化账本字段派生，不由模型另行叙述；召回结果强制标记为资料，不构成指令或授权；每次召回留审计日志。第一版仅开放同 scope 单跳续读，多跳跨对象在权限层验证后再放开。

Watchdog 先以只报不动模式运行并统计误报率，再允许收束动作；任何自动介入不重放已完成任务。

**验收标准**

- 会话未加载时新消息仍在约定时限内被处理，不需要人工打开窗口；唤醒失败有明确状态。
- 精简后每轮仍核验原 ID、摘要与目标；幂等与冻结结果语义不变，回归覆盖不减少。
- 用真实新消息对比改进前后的排队与完成耗时；不以可见轮次减少替代送达证据。
- 双层化与直通不得放宽原生身份准入；Worker 输出仍经原 V2 送达，订阅关系可从私有账本核对。
- Watchdog 只读原回执与日志判定进展，不重放已完成任务；其介入动作留可审计记录。

## M5：固定基线上的 RSI 优化

**剩余范围**

- 按 [PenguinHarness 专项方案](../harness/PENGUIN.md) 建立公开任务集、独立评分规则、留出集和完整基线。
- 固定模型、工具、运行环境与比较条件，先评测一个指令或 Skill 候选，保留失败和退化案例。
- 在候选被证明有效后再接入受控发布；优化器自身的改进另设外层评测。

**验收标准**

- 对同一任务集和基线给出可复现的成功率、耗时、干预成本与退化情况。
- 候选不能接触留出集或修改自己的评分标准；不完整评测不宣布增益。
- 回归通过、提交 PR、工程修复与 RSI 增益分别记录；不以提交数量代替能力提升。
