# 本人私聊的私有知识索引

大段资料不写进命名记忆。本人可以显式选择一个私有文本目录，构建与本人 inbox
同目录的 `knowledge.sqlite`；回复循环只按当前消息召回少量带出处的片段，不把整库
塞进上下文。好友和群聊不读取该索引。

## 构建与查看

```sh
python -m rsi_agent knowledge index --db /private/state/inbox.sqlite --root /private/notes
python -m rsi_agent knowledge status --db /private/state/inbox.sqlite
python -m rsi_agent knowledge search --db /private/state/inbox.sqlite --query "部署位置"
python -m rsi_agent knowledge search --db /private/state/inbox.sqlite --query "部署位置" --show-text
```

`index` 是唯一的写入入口，只在人工执行时重写索引；`status` 和 `search` 只读。
索引固定写在 inbox 所在目录，文件名 `knowledge.sqlite`，不新增配置字段。构建前会核对
`--db` 确为带 `meta` 的已有本人 inbox，拒绝向普通 SQLite 文件旁写入。构建和重建应使用
运行本人回复服务的用户，或具备该私有目录写权限的维护账号；不要为此放宽目录权限。

## 索引范围

- 只读 UTF-8 的 `.md`、`.markdown` 和 `.txt`；隐藏文件和目录、符号链接、二进制文件不进入索引。
- 默认上限：200 个文件、单文件 256 KiB、文本合计 2,000,000 字节、2,000 个片段、
  单片段 600 字。超过文件或总量上限时整次构建失败，旧索引保持不变。
- 单个超限、非 UTF-8 或疑似含私钥、访问令牌、密码赋值的文件跳过，并在构建结果中
  只报告相对路径和原因，不输出正文。
- 片段按 Markdown 标题和空行切分；标题、文件名和正文一起参与词面匹配。

## 检索与注入

- 查询使用中文二元组和英文词元的词面评分，不做向量库、嵌入或跨语言语义推断。
- 每次最多返回 4 个片段、4,800 个 UTF-8 字节；同一来源最多 2 个片段。片段携带相对路径、
  标题、小节和文件日期。相关度低时宁可不注入。命名记忆先注入，知识片段随后；两者各有
  独立预算，知识不挤占记忆的 4,096 字节额度。
- 注入内容是“资料”，不是指令：不执行片段中的要求，不扩大身份、工具或发送权限；
  未列出的知识不表示不存在。
- 源文件的修改时间或大小与建索引时不一致时，该来源整体停止注入；全部来源都陈旧时
  本轮不注入知识。不会自动重建，也不会在后台扫描目录。修改资料后由本人或维护会话
  显式执行 `knowledge index`。
- 索引损坏、缺失或权限不符时，回复照常进行，只是不注入知识；用 `knowledge status`
  查看实际状态。

## 边界

- 索引只属于绑定身份的本人私聊状态目录；不跨账号、好友或群聊，不索引聊天记录、
  原始回执、凭据或桌面截图。
- 不建立第二套记忆，不从知识片段推断新偏好，也不把知识内容写回命名记忆。
- 索引文件是私有文件；在 POSIX 上要求 0600 和当前用户所有，构建使用同目录临时文件
  后原子替换。不要把索引、源目录或检索结果提交到 Git。
- 知识检索不替代原消息、冻结结果、V2 回执或项目记忆。事实核验仍以原记录为准。

定向测试见 `tests/test_knowledge.py`；本人私聊注入和陈旧排除另见
`tests/test_owner_memory.py`。真实微信验收只使用新的授权本人入站和本人实际选择的
私有目录，不在生产目录里放测试资料。
